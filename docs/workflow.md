# 新案場：從平面圖到 3D 初版

固定流程，每個案場都一樣。只有第 2 步需要「看圖」（人或 AI），其餘都是程式。

```
plan.png ──(2. 看圖填寫)──▶ site.yaml ──(3. 編譯 + 驗證)──▶ src/generated/<id>/*.json ──▶ 3D
                                ▲                                                    │
                                └──────────────(4. 疊圖比對，修正 yaml)───────────────┘
```

## 1. 建立案場資料夾

```
sites/<案場id>/
  plan.png      平面圖（png / jpg / webp）
  site.yaml     複製 sites/dc-1f/site.yaml 改
  devices.json  （選用）真實的機櫃內容，有的話會取代假資料
```

`<案場id>` 只用英數和 `-`，且要和 `site.yaml` 裡的 `id` 相同。

## 2. 看圖，填寫 site.yaml

依這個順序填，每一步都有對應的檢查：

| 步驟 | 要做的事 | 怎麼確認 |
|---|---|---|
| 2.1 比例 | 量平面圖上一格地板幾像素 → `plan.pxPerTile`；房間幾格寬、幾格深 → `grid` | 疊圖時格線要對齊 |
| 2.2 圖例 | 列出圖上所有顏色和符號代表什麼；**看不懂的先問，不要猜** | — |
| 2.3 排 | 一排一排記下：方向、中心線、起點、朝向、依序的編號 | 編號不連續會出現警告 |
| 2.4 特殊尺寸 | 比一般寬的設備寫進 `widths` | 疊圖時邊緣對齊 |
| 2.5 牆與門 | 牆寫成矩形；門寫在 `doors`，會自動把牆切開 | — |
| 2.6 封閉通道 | 指定是哪兩排，系統自動算範圍 | 兩排之間沒有空間會報錯 |
| 2.7 點位 | 感測器、攝影機的位置（格） | 疊圖時圖示對齊 |

座標換算：`格 = 像素 ÷ pxPerTile`（如果 `originPx` 不是 0，要先減掉）。

### 交給 AI 做時的指示

> 依照 `docs/workflow.md` 第 2 步和 `docs/site-format.md`，看 `sites/<id>/plan.png`，產生 `sites/<id>/site.yaml`。
> 用 `sites/dc-1f/site.yaml` 當範例。只輸出排與順序，不要逐台估座標。
> 看不懂的圖例、無法確定的朝向，先列成問題問我。
> 完成後執行 `npm run sites`，修正所有 ✖ 錯誤，並在回報中列出所有 ⚠ 警告。

## 3. 編譯與驗證

```bash
npm run sites
```

| 標示 | 意思 | 例子 |
|---|---|---|
| ✖ 錯誤 | 必須修正，否則不會輸出、`npm run build` 也會失敗 | 設備重疊、編號重複、通道沒有空間、排的方向寫錯 |
| ⚠ 警告 | 要人確認 | 編號不連續、設備超出房間、壓到牆、`widths`/`props` 的編號打錯 |

`npm run dev` 執行時，存檔 `site.yaml` 會自動重新編譯並更新畫面。

## 4. 疊圖比對

`npm run dev` → 瀏覽器開 `?site=<案場id>` → 按「俯視」→ 勾「平面圖疊圖」。

逐區檢查：每排的頭尾、門、通道、點位都要和圖對齊。不對就改 `site.yaml` 存檔，畫面會自動更新。

## 5. 需要人確認的清單（每個案場都要問）

- 機櫃正面朝向（平面圖常常沒有標）
- 灰色或不明區塊是牆、柱子還是空位
- 看不懂的設備代號
- 機櫃高度（預設 42U），有沒有不同規格
